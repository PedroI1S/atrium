## Reviewer's report
**Verdict: rework.** The runs support JSON slim deltas, 8 ms batching, and block virtualization as reasonable M1 defaults for this corpus. They do not establish the claimed input or presentation guarantees, and reconnect deduplication and shutdown under backpressure need fixes. `pnpm typecheck` passed; `pnpm test`, `cargo clippy`, and `cargo test` were blocked by sandbox write restrictions. No files were modified, and no app or benchmarks were launched.

1. **Major — Synthetic typing excludes the contention it claims to measure.** [bench.ts:61](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/spikes/stream-perf/src/bench.ts:61) creates and synchronously dispatches each event after its timer finally runs. A busy main thread delays event creation itself, so that delay disappears from `handlerMs` and the subsequent latency measurements. Matching generated and delivered counts is also inherent in this synchronous path. **Fix:** record independently scheduled input deadlines and timer lateness; use externally injected input before claiming “no dropped input.” Qualify the report and handoff’s budget-pass verdict.

2. **Major — Replayed events are applied twice.** [model.ts:128](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/spikes/stream-perf/src/model.ts:128) updates `lastId` but never rejects `ev.id <= lastId`. The client can replay events already forwarded to the webview but not yet acknowledged; those deltas append again and lifecycle events create duplicate rows. The report’s deduplication claim is false. **Fix:** reject duplicates before any model mutation or applied-event counting, and test reconnect before and after delayed acknowledgements. Also deduplicate before the bridge’s corpus-offset mutation at [bridge.rs:362](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/spikes/stream-perf/src-tauri/src/bridge.rs:362), otherwise replay shifts subsequent replacement text.

3. **Major — Stop can deadlock after a hidden or stalled webview triggers backpressure.** [bridge.rs:454](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/spikes/stream-perf/src-tauri/src/bridge.rs:454) removes `Active` before awaiting `StopThread`. Subsequent acknowledgements become no-ops, leaving the pump waiting for credits. Once the client’s bounded event queue fills, it cannot read the command response; the pump is aborted only after that response. **Fix:** introduce a shutdown mode that continues draining events while awaiting stop responses, with a bounded deadline and disconnect fallback. Test stopping with exhausted credits.

4. **Minor — Next-rAF latency is presented as confirmed frame commitment.** [M0-07-stream-perf.md:28](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/docs/spikes/M0-07-stream-perf.md:28) equates the next callback with a committed frame and bounds additional visible latency to approximately 17 ms. [pipeline.ts:97](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/spikes/stream-perf/src/pipeline.ts:97) observes only another callback, without compositor or presentation evidence. GPU/compositor stalls have no demonstrated one-frame bound. **Fix:** call this “agent timestamp → next rAF after model/DOM update,” retain it as a rendering proxy, and remove the presentation bound. Painted-latency claims require presentation tracing.

5. **Minor — The validity policy can discard genuine performance failures.** [bench.py:249](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/spikes/stream-perf/scripts/bench.py:249) rejects low frame counts and long stalls even without visibility evidence; timeouts and errors are also automatically retried as environmental artifacts. The retained invalid runs do contain visibility evidence, so this is **not evidence of cherry-picking those runs**. **Fix:** distinguish independently evidenced environmental invalidation from benchmark failures, and include unexplained stalls/errors in failure reporting.

6. **Minor — The memory explanation exceeds the evidence.** [M0-07-stream-perf.md:106](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/docs/spikes/M0-07-stream-perf.md:106) identifies the transient as uncollected JS garbage and assigns most retained memory to rows and strings. Process footprint and subsequent reclamation cannot establish either attribution. There is also allocation work beyond per-event decoding: changing the count at [Transcript.tsx:35](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/spikes/stream-perf/src/Transcript.tsx:35) makes the pinned virtualizer rebuild count-sized measurement storage. **Fix:** describe the causes as hypotheses and profile JS allocations, virtualizer measurement arrays, cached HTML, and native WebKit memory before selecting a remedy.

7. **Minor — The encoding recommendation compares unequal decode boundaries.** [M0-07-stream-perf.md:158](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/docs/spikes/M0-07-stream-perf.md:158) says binary needs nine times more JS decode time than JSON slim. The streaming JSON measurement excludes Tauri’s JSON parsing, while binary includes decoding. The inclusive microbenchmark actually reports 149 ns/event for binary versus 164 for JSON slim. **Fix:** remove that ratio as a total decode-cost claim. Base the JSON recommendation on comparable end-to-end latency, CPU, and implementation simplicity.

8. **Minor — CR-02 misattributes the daemon peak and needs explicit reconstruction semantics.** [change-requests.md:24](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/docs/agents/change-requests.md:24) attributes 487 MB to building the repeated completion text. The daemon materializes the entire event history at [daemon.rs:330](/Users/pedro/Documents/atrium-wt/M0-07-stream-perf/spikes/daemon-socket/src/daemon.rs:330), including roughly three million envelopes; omitting one 12 MB completion does not remove that cost. Dropping repeated text is sound, but absent text also breaks current reducers’ `text.length` access and completion-only consumers. **Fix:** separate wire-size savings from lifecycle-fold memory, define a versioned inline-text/reference representation, specify reconstruction and delta-retention requirements, and update reducers, adapters, and concatenation fixtures together.
