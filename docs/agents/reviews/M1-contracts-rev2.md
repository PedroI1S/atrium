## New findings

1. **[blocker] User prompts are never stored in `AgentEvent`, `StoredEvent`, or `0001_init.sql`, breaking chat replay, pop-outs, scrollback paging, and thread export.**
   - Where: `crates/atrium-protocol/src/agent.rs:94-263`; `crates/atrium-protocol/src/wire.rs:51-59, 128-133`; `crates/atrium-core/src/history/mod.rs:60-65`; `crates/atrium-core/schema/0001_init.sql:49-70`.
   - Wrong: `TurnStarted` carries only `turn: u32`, `MessageKind` has only `Assistant | Reasoning`, and `turns`/`events` have no user-prompt column or event. When `atrium-client` (`M1-06`) replays a thread on reconnect or pop-out, when `M1-09b` pages back evicted transcript above `MAX_LOADED_TRANSCRIPT_BYTES`, or when `history::export_thread` (`M1-11`) exports `Iterator<Item = StoredEvent>`, every user message in the conversation is missing, and no worker owns `atrium-protocol`.
   - Fix: Add `User` to `MessageKind` (`crates/atrium-protocol/src/agent.rs:259-263`), emitted at turn start (after `SessionStarted` for lazy-init providers) using the existing `MessageDelta`/`MessageCompleted` (`MessageBody`) rules so prompts above `MAX_INLINE_MESSAGE_BYTES` split cleanly and `reconstruct_message`/`export_thread` work unchanged; specify in `m1.md` §8 and `M1-02` that `threads.unread` is set only by `Assistant`/`Reasoning` messages, never `User`.

2. **[blocker] Home auto-allows file overwrites via output redirection, whole-home `rg`/`grep -r` searches, env-var command prefixes, and bare-filename symlinks.**
   - Where: `crates/atrium-core/src/policy/mod.rs:29-44`; `crates/atrium-protocol/src/policy.rs:447-513`; `crates/atrium-core/src/lib.rs:228-231`; `docs/contracts/m1.md:131-138`; `docs/agents/briefs/M1-03-policy.md:25`.
   - Wrong:
     1. `policy/mod.rs:34` and `m1.md:138` reject only `"redirection outside the cwd"`, stripping redirections from `Segment` (`argv`, `piped`). In Home, `cwd` is `~`, so `cat /tmp/payload > ~/.zshrc` or `ls > ~/notes.md` parses as `Segments` with `argv: ["cat", ...]` / `["ls"]` and is auto-allowed without asking by `HOME_READONLY_COMMANDS` (and by any `CommandPrefix` rule).
     2. `HOME_READONLY_COMMANDS` (`policy.rs:485-490`) auto-allows `rg` and `grep` with `only: None` and no target-path guard. Running `rg password` or `grep -rn token .` in Home (`cwd = ~`) recursively searches all of `~` without asking — failing to implement D-050 (`decisions.md:278`), especially for Codex where all searches run via `rg` in `commandExecution`.
     3. Neither `parse_command` nor `HOME_READONLY_COMMANDS` forbids leading `NAME=value` shell assignments (`DYLD_INSERT_LIBRARIES=… ls`, `LD_PRELOAD=… ls`, `GIT_EXTERNAL_DIFF=… git diff`, `PAGER=… git log`).
     4. `PolicyInput::resolved_paths` (`lib.rs:228`) specifies resolving only `"a command's path-like arguments"`. In `cwd = ~`, bare tokens without `/` or `~` (`cat .npmrc`, or `cat notes` where `~/notes` is a symlink to `~/.ssh/id_ed25519` or `atrium.db`) bypass `credential-read` and `atrium-self` if skipped as non-path-like. `tree` (`policy.rs:482`) also guards `-o` without `--output`.
   - Fix: Reject all output/read-write redirections (`>`, `>>`, `>|`, `&>`, `<>`, `[n]>`) and leading `NAME=value` assignments from `HOME_READONLY_COMMANDS` and `CommandPrefix` rules (or return `Unparseable` in `parse_command`); require `rg` and recursive `grep` (`-r`/`-R`/`--recursive`/`-d recurse`) in Home (`cwd == ~`) to ask unless every search target resolves to a strict subdirectory of `~`; add `"--output"` to `tree.forbidden`; and in `SessionGate`, resolve every non-flag argv token (plus `--flag=value` / `key=value` RHS and `ToolSubject::Command.cwd`, tracking or rejecting `cd`) rather than heuristic "path-like" tokens, re-resolving in `SessionGate::redeem` so post-approval symlink swaps cannot hit `Deny`/`HardDeny` targets.

3. **[blocker] `Sanitizer` skips `ToolCheck.subject`, and `AdapterInput` has no variant for `EnforcementDescriptor` in offline fixture replay.**
   - Where: `crates/atrium-agents/src/fixture.rs:137-156`; `crates/atrium-agents/src/lib.rs:301-371`; `crates/atrium-protocol/src/agent.rs:97-111`; `docs/agents/briefs/M1-07-claude-adapter.md:16-21, 33-34`.
   - Wrong:
     1. `ToolCheck` gained `pub subject: ToolSubject` (`lib.rs:267`), holding raw command lines, `cwd`, file paths, and URLs, but `Sanitizer::input` (`fixture.rs:137-156`) sanitizes only `check.input` and `check.title` on `AdapterInput::Gate` and `Redeem`. Live recordings in `M1-07` (`:33`) will retain `/Users/<user>` and canary secrets inside `check.subject` and fail the required `Sanitizer::is_clean` check, while `fixture.rs` is outside `M1-07` and `M1-08` owned paths.
     2. `Normalizer::on_input` is pure (`lib.rs:364-370`) and `fixture::assert_golden` (`fixture.rs:51`) replays only `FixtureLine` (`AdapterInput`) items, yet `AdapterInput` has no variant recording the `EnforcementDescriptor` inspected from disk at start or updated mid-session. `ClaudeNormalizer` and `CodexNormalizer` cannot deterministically emit `SessionStarted.enforcement` (e.g. `M1-07`'s required `plugin-hook` fixture, `:34`) or `EnforcementChanged` from `.jsonl` fixtures.
   - Fix: Sanitize `check.subject` (`Command { line, cwd }`, `Paths { paths, glob, .. }`, `Fetch { url }`) in `Sanitizer::input`, and add `AdapterInput::Enforcement { descriptor: EnforcementDescriptor }` (recorded at session start and on changes, with `ConfigSource.path` and `reasons` sanitized in `Sanitizer::input`).

4. **[blocker] `Store` omits `rename` for `DaemonCommand::RenameThread`, and `AppIdentity::Linux` cannot be compiled into release daemons.**
   - Where: `crates/atrium-core/src/lib.rs:120-210`; `crates/atrium-protocol/src/wire.rs:210-213`; `crates/atrium-host/src/peer.rs:13-33, 59-62`.
   - Wrong:
     1. Rev 2 added `DaemonCommand::RenameThread { thread_id, title }` (`wire.rs:210-213`), but `atrium_core::Store` (`lib.rs:120-210`) and `M1-02-store.md` still have no `rename` method. `M1-05` (`atriumd`) cannot persist thread renames (or first-message title updates after `StartThread { message: None }`) without editing frozen `atrium-core/src/lib.rs` and `M1-02`-owned `store/`.
     2. `peer.rs:13-16` and `m1.md:69` require release builds on Linux to compile `AppIdentity::Linux` into `atriumd`, yet `AppIdentity::Linux` (`peer.rs:28-33`) requires `dev: u64` and `ino: u64` — filesystem device and inode numbers assigned on each user's machine at install time, never known at compile time. `peer.rs:59` also permits `"pidfd_open immediately"` as a fallback to `SO_PEERPIDFD`, which allows a PID-recycle race if a peer forks a child holding the socket and exits before `pidfd_open(pid)` runs.
   - Fix: Add `fn rename(&self, thread: &ThreadId, title: &str) -> BoxFuture<'_, StoreResult<ThreadSummary>>` to `Store` (and `M1-02-store.md`); change `AppIdentity::Linux` to `dev_ino: Option<(u64, u64)>` (`None` compiled into release builds, where `verify_app_peer` checks root/non-user-writable ownership on `executable` and `stat`s it at runtime; `Some((dev, ino))` in dev builds), and require `SO_PEERPIDFD` without a `pidfd_open(pid)` fallback.

5. **[major] `requests.event_closed DEFAULT 0` emits orphan `RequestResolved` on pre-event crashes, and `RequestStore` lacks `current_incarnation` and CAS rule semantics.**
   - Where: `crates/atrium-core/schema/0001_init.sql:96-115`; `crates/atrium-core/src/lib.rs:89-100, 294-295, 307-337`; `docs/agents/briefs/M1-02-store.md:27-28, 31`; `crates/atrium-core/tests/ledger.rs:23-26, 46-50`.
   - Wrong:
     1. `RequestStore::open_approval`/`open_question` inserts into `requests` with `event_closed = 0` inside `ToolGate::check`/`question_ticket`, *before* `ApprovalRequested`/`QuestionAsked` is emitted or stored. If `atriumd` crashes in that window (or the adapter aborts before emitting the event), `Store::open_items` (`event_closed = 0`) returns a `request_id` with no prior `ApprovalRequested`/`QuestionAsked` in `events`, causing startup recovery (`m1.md:87`) to append an invalid orphan `RequestResolved`. `open_question` also stores no `prompt` for `requests.title` when recomputing `attention_detail` (`M1-02-store.md:31`), and `tests/store.rs` tests appending `ApprovalRequested` without calling `RequestStore` get empty `open_items().requests`.
     2. `Ledger` holds only `Arc<dyn RequestStore>` (`policy/mod.rs:58`), which has no method returning a thread's current incarnation, so `Ledger::resolve` cannot return `LedgerError::StaleIncarnation` (`tests/ledger.rs:24`) across restarts or before a new incarnation opens its first request.
     3. `RequestStore::approve_with_rule` (`lib.rs:320-325`) is omitted from `M1-02-store.md` and does not state that inserting `rule` and incrementing `rules_revision` must happen *only* if the CAS from `'pending'` to `'approved'` succeeds.
   - Fix: Track open transcript requests in an `open_requests(thread_id, incarnation, request_id, kind, at_ms, detail)` projection table in `0001_init.sql` (inserted by `Store::append` on `ApprovalRequested`/`QuestionAsked` and deleted on `RequestResolved`); add `fn current_incarnation(&self, thread: &ThreadId) -> BoxFuture<'_, StoreResult<Option<u32>>>` to `RequestStore`; and specify on `approve_with_rule` (and in `M1-02-store.md`) that `rule` and `rules_revision` are written only when `status` was `'pending'`.

6. **[major] `attention::next_state` cannot implement `Signal::Stopped` or "exit with a turn open" from its stateless signature as worded.**
   - Where: `crates/atrium-core/src/attention/mod.rs:21-35`; `crates/atrium-protocol/src/thread.rs:30-50`; `docs/agents/briefs/M1-04-attention.md:20`; `crates/atrium-core/tests/attention.rs:34-37`.
   - Wrong: `next_state(current: &ThreadState, pending: Pending, input: AttentionInput<'_>) -> ThreadState` is stateless and `ThreadState` has no `Stopping` variant. *"After `Signal::Stopped`, the exit is `Ended` whatever its code"* cannot hold unless `Signal::Stopped` transitions immediately to `Ended` **and** `Ended` is sticky (like `Failed` and `Paused`) across the closing `TurnCompleted`/`SessionEnded` events and `Signal::Exited` that follow. Likewise, *"an exit with a turn open, or a non-zero code, is `Interrupted { cleanup: Verified }`"* cannot see an open turn at `SessionEnded`/`Signal::Exited` because closing always emits `TurnCompleted { outcome: Interrupted }` *before* `SessionEnded` (`agent.rs:25-27`), moving `Running → Idle` (indistinguishable from a user `Interrupt` followed later by clean exit `0`).
   - Fix: State in `attention/mod.rs` and `M1-04-attention.md` that `Signal::Stopped` transitions directly to `ThreadState::Ended` and `Ended` is sticky through closing events and `Signal::Exited` until `Signal::Starting`; and either add `turn_open: bool` (captured before closing) to `Pending` or define exit transitions strictly from `current` and `exit_code` (`Some(0)` from `Idle` → `Ended`; non-zero/`None` or raw exit from active states → `Interrupted { cleanup: Verified }`).

8. **[major] `PolicyInput::atrium_paths` conflates read-blocked and write-only paths, `SessionGate` can offer dead/broken "always…" rules, and `kill_recorded` permits PID-wraparound kills.**
   - Where: `crates/atrium-core/src/lib.rs:225-227`; `crates/atrium-protocol/src/policy.rs:389-391, 397-399`; `crates/atrium-core/src/policy/mod.rs:73-75`; `crates/atrium-host/src/supervise.rs:70-75`.
   - Wrong:
     1. D-050 (`decisions.md:270, 273`) and `policy.rs:398` block *reading and writing* Atrium's data (DB, WAL, snapshots, logs) and `~/.ssh` private keys, while blocking *writing* Atrium's config, socket, service units, app binary, and `~/.ssh/config` + `authorized_keys` (`policy.rs:390` words `~/.ssh/config` as read-or-write). Passing one undifferentiated `atrium_paths: &'a [PathBuf]` (`lib.rs:227`) gives pure `DefaultPolicy` no way to allow reads while blocking writes on config/service/app paths.
     2. In `SessionGate::check` (`policy/mod.rs:73-75`), offering `CommandPrefix` on commands containing `$`/globs/redirections creates rules `DefaultPolicy` will never match (`m1.md:138`), and unescaped `PathGlob` on paths containing `[`/`*`/`?` (e.g. `app/[id]/page.tsx`) or multi-path edits (`paths.len() != 1`) misbehaves.
     3. `supervise::kill_recorded` (`supervise.rs:71-73`) implies processes in `-pgid` with `start_time >= recorded.start_time` can be killed even when `identify(recorded.pid)` is `None`; on macOS (`PID_MAX = 99999`), an unrelated group reusing `pgid` after a crash also has `start_time >= recorded.start_time`.
   - Fix: Split `PolicyInput` into `atrium_data_paths: &'a [PathBuf]` (no read or write) and `atrium_protected_paths: &'a [PathBuf]` (no write), and align `policy.rs:390` on write-blocking `~/.ssh/config` and `authorized_keys`; set `remember_matcher = None` unless a command is simple/literal or `paths.len() == 1` (with glob metacharacters escaped); in `supervise.rs:70-74`, when `identify(recorded.pid)` is `None`, return `Verified` iff `kill(-pgid, 0)` fails with `ESRCH` and `Unverified` (never killing) otherwise.
