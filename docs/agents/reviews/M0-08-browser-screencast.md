## Reviewer's report
**Approve with changes.** The spike supports the pipe transport recommendation and provides a credible in-app fps/click-to-canvas method, with useful limits documented. Lifecycle safety, context switching, and input handling need fixes before reuse in M1/M3. Typecheck passed; Vitest, Clippy, and Rust unit tests were blocked by sandbox write restrictions. I changed nothing and launched no browser.

1. **Major — Reaper can terminate an unrelated or actively owned process.** [browser.rs:99](/Users/pedro/Documents/atrium-wt/M0-08-browser-screencast/spikes/browser-screencast/src-tauri/src/browser.rs:99) accepts any command containing the profile path, including a shell/editor command or a longer profile name. It also never checks whether the previous owner is alive, so a second app instance using the default data directory kills the first instance’s browser. **Fix:** lock the profile for its owner’s lifetime; record and verify process start time, executable identity, and the exact profile argument before signaling. Refuse launch when another live owner holds the lock.

2. **Major — Frames and acknowledgments can cross context switches.** [controller.ts:74](/Users/pedro/Documents/atrium-wt/M0-08-browser-screencast/spikes/browser-screencast/src/pane/controller.ts:74) resets sequence tracking while old `createImageBitmap` calls remain pending. Their completions can draw context A after switching to B and cause B’s lower sequence numbers to be discarded. Meanwhile, [lib.rs:271](/Users/pedro/Documents/atrium-wt/M0-08-browser-screencast/spikes/browser-screencast/src-tauri/src/lib.rs:271) sends every acknowledgment to whichever stream is currently active. **Fix:** assign each attachment a generation; reject stale decode completions and route acknowledgments using the originating stream/session. Test switching with a deliberately delayed decoder.

3. **Major — Take-over does not stop an already admitted agent action.** [lib.rs:366](/Users/pedro/Documents/atrium-wt/M0-08-browser-screencast/spikes/browser-screencast/src-tauri/src/lib.rs:366) checks control once, before several awaits. The user can take over while an agent navigation or click remains in progress; the navigation retry can issue another command afterward. This contradicts the stated protection against interleaved input. **Fix:** serialize ownership changes with input dispatch, invalidate queued agent work on take-over, and make the toggle complete only after prior work has been canceled or drained.

4. **Minor — The chromiumoxide latency comparison uses different endpoints.** [screencast-oxide-probe.rs:87](/Users/pedro/Documents/atrium-wt/M0-08-browser-screencast/spikes/browser-screencast/src-tauri/examples/screencast-oxide-probe.rs:87) timestamps frames when the consumer retrieves them, after awaiting both mouse commands. The own-client bench uses timestamps captured by its pipe reader. The reported approximately 3 ms difference therefore does not compare equivalent measurements. The oxide probe also never verifies JPEG dimensions despite the documented `--enable-automation` size issue. **Fix:** use equivalent timestamp locations and record decoded dimensions for both probes; qualify the comparison until rerun.

5. **Major — The IME sink clears marked text during composition.** [Pane.tsx:87](/Users/pedro/Documents/atrium-wt/M0-08-browser-screencast/spikes/browser-screencast/src/pane/Pane.tsx:87) empties the textarea on every `input`, including composition updates. This overwrites the native input method’s active text. Existing screenshots and live tests call the controller/CDP methods directly and bypass this handler. **Fix:** track composition state and preserve the sink’s value until composition ends; verify multi-update composition, commit, and cancellation through the textarea.

6. **Minor — Releasing the mouse outside the canvas loses mouse-up.** [Pane.tsx:51](/Users/pedro/Documents/atrium-wt/M0-08-browser-screencast/spikes/browser-screencast/src/pane/Pane.tsx:51) listens only on the canvas and captures no pointer. Pressing inside, moving outside, then releasing leaves Chromium without the release event, breaking ordinary selection and dragging. **Fix:** use pointer capture and release held buttons on cancellation, window blur, context changes, and control hand-back.

7. **Minor — The interactive 2x toggle does not produce the documented 2x stream.** [App.tsx:33](/Users/pedro/Documents/atrium-wt/M0-08-browser-screencast/spikes/browser-screencast/src/App.tsx:33) changes emulation and canvas backing dimensions without restarting Chromium with the required launch flag. A default launch therefore displays an enlarged 1x image while the status reports the larger canvas size. **Fix:** restart with the required flag, or disable/label the toggle appropriately; report decoded frame dimensions separately from canvas dimensions.

8. **Minor — Isolation screenshots do not demonstrate isolation between coexisting contexts.** [screenshots.sh:33](/Users/pedro/Documents/atrium-wt/M0-08-browser-screencast/spikes/browser-screencast/scripts/screenshots.sh:33) captures A and B from separate launches with separate profiles. The B scene never writes A’s state first; the screenshots visibly have different browser PIDs and fixture ports. The live isolation test is stronger evidence, but the report overstates what these images show. **Fix:** write A’s state, capture A, switch to B, and capture B within one launch. Correct the report and handoff accordingly.

9. **Minor — CDP EOF does not terminate event consumers.** [cdp.rs:215](/Users/pedro/Documents/atrium-wt/M0-08-browser-screencast/spikes/browser-screencast/src-tauri/src/cdp.rs:215) fails pending calls and marks the connection closed, but retains the broadcast sender in `Inner`. Pages retain `Cdp`, so `FrameStream::next()` can wait indefinitely after browser exit rather than returning `None` as documented. **Fix:** propagate explicit connection cancellation to event consumers and test EOF with a waiting frame subscriber before adopting this client for M1/M3.
