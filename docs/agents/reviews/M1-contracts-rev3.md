## New findings

1. **[blocker] Attached short-flag paths (`-f.npmrc`), `-f` in `file`/`rg`/`grep`, `key=value` operands, and flag-consumed words bypass `credential-read` and whole-home search guards.**
   - Where: `crates/atrium-core/src/policy/mod.rs:116-118`; `crates/atrium-protocol/src/policy.rs:470-472, 484-489, 509-534`; `docs/contracts/m1.md:142`; `docs/agents/briefs/M1-03-policy.md:32`.
   - Wrong: `SessionGate::check` resolves only non-flag arguments, `--flag=value` values, and redirect targets (`policy/mod.rs:116-118`), while `HOME_READONLY_COMMANDS` in frozen `atrium-protocol` permits `-f` on `file`, `rg`, and `grep` (`policy.rs:486, 512, 524`). In Home (`cwd = ~`), `file -f.npmrc` or `file -flink` (where `~/link` targets `~/.ssh/id_ed25519` or `atrium.db`) is neither resolved by `SessionGate` nor forbidden by `file`, so it auto-allows without asking and prints every line of the secret file (`<line>: cannot open`); `rg -f.npmrc sub/` and `grep -f.ssh/id_ed25519 x sub/a` likewise auto-allow reading credential files, `dd if=link` and `Segment::assignments` (`VAR=link`) skip symlink canonicalization for `HardDeny`, and `rg -e sub` / `grep -r -e sub` auto-allows a whole-home search if value-taking flags (`-e`, `-g`, `-t`, `-m`, …) are not recognized as consuming the next word rather than naming a search root.
   - Fix: Add `"-f"`, `"--files-from"` to `file.forbidden` and `"-f"`, `"--file"` to `rg.forbidden` and `grep.forbidden` in `crates/atrium-protocol/src/policy.rs`; in `SessionGate` (`policy/mod.rs:116-118`, `m1.md:142`), also resolve attached short-flag values (`-Xvalue` / `-X=value` when `arg.len() > 2`), `key=value` argv operands, and `Segment::assignments` values (skipping `RedirectOp::Dup` fd numbers); and state on `HOME_READONLY_COMMANDS` (`policy.rs:470-472`, `M1-03-policy.md:32`) that `rg`/`grep` flags taking a separate argument consume the next token instead of counting it as a search root (asking on unknown flags).

2. **[major] Non-literal directory changes after `cd <literal>` keep the subfolder `cwd` and turn `HardDeny` into `Ask`.**
   - Where: `crates/atrium-core/src/policy/mod.rs:119-121`; `docs/contracts/m1.md:142`.
   - Wrong: `SessionGate` updates the segment `cwd` on `cd` to a literal path, while `"any other directory change (cd -, cd $X, pushd) makes the line Ask"` leaves the running `cwd` at that prior subfolder. In Home (`cwd = ~` with subfolder `~/tmp`), `cd tmp && cd && rm -rf .`, `cd tmp && cd - && rm -rf .`, or `cd tmp && pushd / && rm -rf .` resolves `.` against `~/tmp` instead of `~` or `/`, and `cd tmp && cd && cat .npmrc` resolves `.npmrc` to `~/tmp/.npmrc` — turning `recursive-delete-outside-cwd` and `credential-read` (`HardDeny`) into `Ask` (contrary to `m1.md:90`).
   - Fix: Resolve bare `cd` (no arguments) to `home`, `pushd <literal>` like `cd <literal>`, and `cd -` to the previous known segment `cwd`; after any unresolvable directory change (`cd $X`, `popd`, `cd -` with no prior `cd`), mark the segment `cwd` unknown so rules/presets `Ask`, any relative recursive delete (`rm -r`, `find -delete`) hits `recursive-delete-outside-cwd`, and relative tokens are still checked against `home` and the initial `cwd` for `HardDeny`.

3. **[minor] Stale pre-rev-3 sentences remain in `M1-02-store.md` and `M1-10-host.md`.**
   - Where: `docs/agents/briefs/M1-02-store.md:27`; `docs/agents/briefs/M1-10-host.md:22`.
   - Wrong: `M1-02-store.md:27` still says "`open_items().requests` are the rows with `event_closed = 0`", contradicting line 29 (`event_opened = 1 AND event_closed = 0`); `M1-10-host.md:22` still says `kill_recorded` checks for "remaining processes that can't be shown to descend from it", whereas `supervise.rs:70-74` and `m1.md:155` now state start times cannot prove descent and any non-empty group with a gone leader is `Unverified`.
   - Fix: Delete the stale sentence in `M1-02-store.md:27` and align `M1-10-host.md:22` with `supervise.rs:70-74`.
