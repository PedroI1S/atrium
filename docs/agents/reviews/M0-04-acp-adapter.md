## Reviewer's report
**Rework.** The live fixtures support the verified gating paths, but inherited agent permissions can undo the Code Mode mitigation, and the adapter has lifecycle and event-delivery defects. The saturation test does not establish the required shutdown guarantees. Both permitted Cargo commands were blocked by the read-only sandbox at `.cargo-build-lock`, so I have no fresh test results.

1. **Blocker — Inherited agent rules can re-enable Code Mode.** [opencode_config.rs:78](/Users/pedro/Documents/atrium-wt/M0-04-acp-adapter/spikes/agent-acp/src/opencode_config.rs:78) overrides only `explore` and `general`. An inherited `agents.build.permissions` rule allowing `execute`, or an equivalent custom agent, remains intact and overrides the global deny: agent rules are appended after global rules. That restores the ungatable JavaScript/network path. **Fix:** enforce the final rules on every effective agent, including `build` and custom agents, or disable agents whose effective permissions cannot be constrained; verify that managed configuration cannot restore `execute` before accepting startup. Add conflicting-config coverage. [OpenCode permission precedence](https://opencode.ai/v2/docs/permissions/)

2. **Major — Cancelled approvals remain executable in runtime state.** [adapter.rs:1012](/Users/pedro/Documents/atrium-wt/M0-04-acp-adapter/spikes/agent-acp/src/adapter.rs:1012) clears the active prompt but leaves `pending_approvals` and `pending_questions`. Meanwhile, the normalizer cancels those requests when the turn completes. A subsequent stale `ResolveApproval::Allow` produces the contract’s “already resolved” error but still reaches `complete_pending_approval` at line 941; a pending client filesystem or terminal operation can execute. **Fix:** retire runtime requests together with normalized requests, and ensure rejected commands cannot perform I/O. Test an outstanding approval followed by turn completion and a late allow.

3. **Major — Terminal waiting blocks Interrupt and Shutdown.** [adapter.rs:1524](/Users/pedro/Documents/atrium-wt/M0-04-acp-adapter/spikes/agent-acp/src/adapter.rs:1524) awaits the terminal process inline in the sole session loop. A long-running command followed by `terminal/wait_for_exit` prevents that loop from handling either control command. The unbounded gate await at line 1120 has the same responsiveness problem. **Fix:** handle terminal completion and gate decisions as cancellable pending work selected alongside commands; keep terminal killing independent of a lock held across `wait()`.

4. **Major — Usage reports session context and cost as turn totals.** [normalizer.rs:834](/Users/pedro/Documents/atrium-wt/M0-04-acp-adapter/spikes/agent-acp/src/normalizer.rs:834) maps ACP `UsageUpdate.used`—tokens currently in context—to `input_tokens`, and cumulative session cost directly to turn cost. It also preserves the first `used` value throughout a turn. The live `multi-turn` golden visibly reports 8,192 input tokens before replacing them with 125 at completion. Nonzero session costs would be counted repeatedly across turns. **Fix:** keep context occupancy separate, derive turn cost from session-cost differences, and use actual prompt usage for token totals; leave unavailable fields `None`.

5. **Major — Shutdown can discard the required closing events.** [adapter.rs:1740](/Users/pedro/Documents/atrium-wt/M0-04-acp-adapter/spikes/agent-acp/src/adapter.rs:1740) aborts forwarding immediately after enqueueing normalized exit events. When the public event channel is full, the forwarding task breaks at lines 309–320 and drops the remaining events, including `RequestResolved`, `TurnCompleted`, and `SessionEnded`. A receiver that resumes reading sees an incomplete lifecycle. **Fix:** separate process shutdown from event delivery and preserve ordered closing events until delivered or the receiver is dropped. Add a fill–shutdown–drain test.

6. **Major — The saturation test measures enqueueing, not shutdown.** [live_adapter.rs:144](/Users/pedro/Documents/atrium-wt/M0-04-acp-adapter/spikes/agent-acp/tests/live_adapter.rs:144) stops its timer once two commands enter the command channel. That succeeds even if the session loop never processes them. It neither verifies saturation nor observes cancellation, child reaping, or task termination. **Fix:** establish saturation explicitly, observe the mock receiving cancellation, and await adapter completion and child reaping within the bound while keeping events unread.

7. **Major — The bypass checker accepts denied or late-gated execution.** [selfcheck.rs:131](/Users/pedro/Documents/atrium-wt/M0-04-acp-adapter/spikes/agent-acp/src/selfcheck.rs:131) treats any `Gate` record with the call ID as proof of gating, regardless of its decision or position. Thus `Gate::Deny → completed`, unresolved `Ask → completed`, and `completed → Gate::Allow` all pass the general checker. Failed tools are also excluded even though failure can follow side effects. **Fix:** track authorization chronologically, require an effective allow before execution evidence, and distinguish failure before execution from failure after execution.

8. **Minor — Failed updates lose replacement fields.** [normalizer.rs:996](/Users/pedro/Documents/atrium-wt/M0-04-acp-adapter/spikes/agent-acp/src/normalizer.rs:996) finishes a failed call without emitting its replacement title, kind, or input, although those fields were parsed and stored internally. Additionally, `extract_tool_output` at line 1982 treats an explicitly empty content replacement as unchanged. **Fix:** emit replacement fields before every terminal status and preserve empty replacements, with focused failed-update and output-clearing cases.

9. **Minor — Resume-only agents receive the unsupported load method.** [adapter.rs:602](/Users/pedro/Documents/atrium-wt/M0-04-acp-adapter/spikes/agent-acp/src/adapter.rs:602) accepts `sessionCapabilities.resume` when `loadSession` is false, but unconditionally sends `session/load` at line 622. **Fix:** select `session/resume` and its request type when only resume is advertised; add a mock advertising that combination.

10. **Minor — The enforcement report and handoff contradict current evidence.** [M0-04-acp-adapter.md:59](/Users/pedro/Documents/atrium-wt/M0-04-acp-adapter/docs/spikes/M0-04-acp-adapter.md:59) says `tool-fetch` preserves the ungated Code Mode call, but the current fixture records gated `webfetch`. The report still marks fetch unexercised and round-two recording pending, as does the [handoff:3](/Users/pedro/Documents/atrium-wt/M0-04-acp-adapter/docs/agents/handoffs/M0-04-acp-adapter.md:3). **Fix:** update the matrix and handoff to the current recordings, distinguish ACP kind `execute` from the tool named `execute`—the current probe used `shell`—and retain historical bypass evidence under a separate fixture name if it remains cited.
