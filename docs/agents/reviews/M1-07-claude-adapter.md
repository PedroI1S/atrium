# Review: M1-07-claude-adapter
Reviewer: Gemini 4 Argon (read-only) · 2026-11-12
## Verdict
**rework**: Two security-boundary blockers (in-flight `gate.check` completions answering `allow` after request cancellation or turn end, and `Glob` subjects omitting `pattern` from `paths` so `DefaultPolicy` misses parent-directory or absolute paths and `credential-read` hard-denies) plus five major protocol/enforcement defects require fixes before merge.

## Findings
1. [blocker] **In-flight `gate.check` task completing after `control_cancel_request` or `"result"` answers `allow`/`ask` to a cancelled or ended request and leaks stale approvals across turns**
   - Where: `crates/atrium-agents/src/claude/adapter.rs:958-963` (`Driver::on_stdout` `"result"`), `crates/atrium-agents/src/claude/adapter.rs:990-998` (`Driver::on_control_cancel_request`), `crates/atrium-agents/src/claude/adapter.rs:1225-1266` (`Driver::on_gate_decision`), and `crates/atrium-agents/src/claude/normalizer.rs:1002-1033` (`ClaudeNormalizer::gate`).
   - Sequence:
     1. Start a session (`ClaudeAdapter::start`), send `SessionCommand::SendUserMessage { text: "run".into() }`, and emit stdout `{"type":"system","subtype":"init","cwd":"/tmp","session_id":"s1","model":"claude-haiku-5-5","claude_code_version":"2.1.308"}` followed by `{"type":"stream_event","api_message_id":"m1","event":{"type":"message_start","message":{"id":"m1","model":"claude-haiku-5-5","usage":{"input_tokens":1,"output_tokens":1}}}}`.
     2. Emit stdout `{"type":"control_request","request_id":"r_can","request":{"subtype":"can_use_tool","tool_name":"Bash","tool_use_id":"toolu_1","input":{"command":"echo hi"}}}` while `SessionGate::check` is still pending on `self.gates` (`adapter.rs:1094-1101` inserts `"r_can"` into `self.live` and spawns `gate.check`).
     3. Before the spawned `gate.check` future resolves, emit stdout `{"type":"control_cancel_request","request_id":"r_can"}` (or `"result"` ending turn 1, e.g. `{"type":"result","subtype":"success","is_error":false,"result":"done"}`). `forget_native("r_can")` (`adapter.rs:1203`) removes `"r_can"` from `self.live` (or `clear_requests()` at `adapter.rs:961, 1219` clears `self.live`, `self.hook_asked`, `self.approvals`, and `self.questions`, without aborting `self.gates`).
     4. Allow the in-flight `gate.check` task to resolve with `Ok(GateDecision::Allow)` (or `Ok(GateDecision::Ask { ticket })` with `ticket.request_id = "T1"`).
     5. (Variant B — hook path across turn boundary): In step 2, emit `{"type":"control_request","request_id":"r_hook","request":{"subtype":"hook_callback","callback_id":"atrium-pre-tool-use","tool_use_id":"toolu_1","input":{"hook_event_name":"PreToolUse","tool_name":"Bash","tool_use_id":"toolu_1","tool_input":{"command":"echo hi"}}}}`; in step 3, emit `"result"` ending turn 1 while `SendUserMessage` for turn 2 is queued (`dispatch_next()` starts turn 2); in step 4, `gate.check` resolves with `Ok(GateDecision::Allow)` or `Ok(GateDecision::Ask { ticket: T1 })`.
   - Result:
     - In `on_gate_decision` (`adapter.rs:1243-1247`), `Reply::CanUse` on `GateDecision::Allow` calls `self.live.remove(&request_id);` (ignoring the `false` return value) and unconditionally sends `{"type":"control_response","response":{"subtype":"success","request_id":"r_can","response":{"behavior":"allow","updatedInput":{"command":"echo hi"}}}}` on stdin for a cancelled or turn-ended request.
     - On `GateDecision::Ask { ticket: T1 }` (`adapter.rs:1253-1264`), `Reply::CanUse` does not check `self.live.contains(&request_id)` at all and inserts `PendingApproval` into `self.approvals` after `forget_native` / `clear_requests` already ran. If `"result"` had cleared `normalizer.can_use`, `normalizer.rs:1030` puts `("toolu_1", T1)` into `self.asked` for the next turn without emitting `ApprovalRequested`, while `self.approvals` holds `T1`.
     - In Variant B (`Reply::Hook`, `adapter.rs:1232-1241`), `request_id` is never tracked in `self.live`; when `gate.check` finishes after `"result"`, `on_gate_decision` writes `permissionDecision: "allow"` or `"ask"` to stdin for the ended turn's hook and inserts `("toolu_1", T1)` into `self.hook_asked` and `normalizer.asked` in turn 2.
     - Violates `crates/atrium-agents/src/lib.rs:34` ("A tool call never runs unless the `SessionGate` says so") and the review brief §1 (never send an answer after the turn or session ended or after withdrawal).
   - Fix: Track `Reply::Hook`'s `request_id` in `self.live` when `on_hook` spawns a gate check (`adapter.rs:1049`); in `on_gate_decision` (`adapter.rs:1225`), check `if !self.live.remove(reply.request_id()) { return; }` before feeding `AdapterInput::Gate` or calling `respond` / `hook_decision`; and call `self.gates.abort_all()` + `self.redeems.abort_all()` inside `clear_requests()` (`adapter.rs:1217`).

2. [blocker] **`Glob` tool subject places `pattern` only in `glob` and defaults `paths` to `["."]`, bypassing `DefaultPolicy` root/outside-workspace checks and `credential-read` hard-denies in `Preset::Home`**
   - Where: `crates/atrium-agents/src/claude/tools.rs:72-76` (`tool_subject` `"Glob"` arm), interacting with `crates/atrium-core/src/policy/deny.rs:127-138, 1061-1088` (`analyze_with`, `Ctx::search_glob_hit`) and `crates/atrium-core/src/policy/engine.rs:564-578` (`Home::evaluate`).
   - Sequence:
     1. Construct a `SessionGate` with `DefaultPolicy::new(PolicyConfig::new(Preset::Home))`, `home = "/home/ana"`, and `cwd = "/home/ana/work"` (or start a session in `/home/ana/work` under `Preset::Home`).
     2. Emit stdout `control_request` (`hook_callback` for `PreToolUse`) with `tool_name: "Glob"`, `tool_use_id: "toolu_glob_1"`, and `tool_input: {"path": "/home/ana/work", "pattern": "/home/ana/.ssh/id_ed25519"}` (or `{"pattern": "/home/ana/.ssh/id_ed25519"}` with no `"path"` field, or `{"path": "sub", "pattern": "/etc/passwd"}`, or a relative parent-traversal pattern into `.ssh/id_ed25519`).
   - Result:
     - `tools::tool_subject` (`tools.rs:72-76`) returns `ToolSubject::Paths { paths: vec!["/home/ana/work"], glob: Some("/home/ana/.ssh/id_ed25519"), recursive: true }` (or `paths: vec!["."]`).
     - In `atrium_core::policy::deny::analyze_with` (`deny.rs:127-138`), only `paths` (not `glob`) are resolved into `a.uses` (`/home/ana/work`).
     - In `Ctx::search_glob_hit` (`deny.rs:1061-1088`), `probe` resolves to `/home/ana/.ssh/id_ed25519`, and `root_paths.iter().any(|r| under(&probe, &lower(r)).is_some())` checks whether `/home/ana/.ssh/id_ed25519` is under `/home/ana/work`. It is not, so `search_glob_hit` returns `None` (no `credential-read` hard-deny)!
     - In `Home::evaluate` (`engine.rs:564-578`), `roots.iter().all(|r| self.root_ok(r))` checks `/home/ana/work`, which is inside `/home/ana` and not a sensitive ancestor, so `DefaultPolicy` returns `PolicyVerdict::Allow` and the adapter answers `permissionDecision: "allow"` to a `Glob` reading `~/.ssh/id_ed25519` or `/etc/passwd`.
     - Furthermore, for both `"Glob"` and `"Grep"` (`tools.rs:72-86`), if `"path"` is `""` or a non-string (e.g. `{"path": 123, "pattern": "foo"}`) or `"Glob"` is missing `"pattern"` (`{}`), `s("path")` returns `None` and `.unwrap_or_else(|| ".".to_owned())` substitutes `"."` instead of returning `ToolSubject::Unknown`.
     - Violates `crates/atrium-agents/src/lib.rs:34-40` and brief §"Tool subjects (`tools.rs`)".
   - Fix: In `tools.rs:72-86`, reject missing/empty `"pattern"` on `"Glob"` and non-string/empty `"path"` on `"Glob"`/`"Grep"` by returning `ToolSubject::Unknown`. For `"Glob"`, when `"pattern"` contains path separators (`/` or `\`), parent-directory segments, or starts with `~`, resolve/join it against `base_dir` (`path` or `"."`) and include that target path in `paths` (or if `pattern` has no wildcard characters, pass the joined path in `paths` so `a.uses` includes the actual target path).

3. [major] **`on_can_use` and `normalizer::emit_approval` do not check `MAX_PARTIAL_ARGS_BYTES`, allowing >4 MiB tool inputs into `ToolCallStarted` and `ApprovalRequested` (exceeding `MAX_EVENT_BYTES` and crashing the session in the daemon)**
   - Where: `crates/atrium-agents/src/claude/adapter.rs:946, 985-986, 1061-1102` (`Driver::on_stdout`, `Driver::on_control_request`, `Driver::on_can_use`) and `crates/atrium-agents/src/claude/normalizer.rs:562-590, 872-933` (`ClaudeNormalizer::tool_use`, `can_use_tool`, `emit_approval`).
   - Sequence:
     1. Start a session with a gate that returns `GateDecision::Ask` for `Edit` (e.g. `Preset::Balanced` on a protected path or `ApprovalPolicy::AlwaysAsk`).
     2. Establish the session (`system/init` + `stream_event` `message_start`).
     3. Case A (`can_use_tool` before `assistant` `tool_use`, as on subagent calls): Emit stdout `control_request` (`subtype: "can_use_tool"`, `request_id: "r1"`, `tool_name: "Edit"`, `tool_use_id: "toolu_big"`, `input: {"file_path": "/etc/hosts", "old_string": "a", "new_string": "<4.5 MiB string>"}`) whose line length is 4.5 MiB (`> MAX_PARTIAL_ARGS_BYTES` = 4 MiB, `< MAX_PROVIDER_RECORD_BYTES` = 8 MiB). Then emit the matching `assistant` `tool_use` record with `id: "toolu_big"` and the same 4.5 MiB `input`.
     4. Case B (`assistant` `tool_use` before `can_use_tool`): First emit the `assistant` `tool_use` record with `id: "toolu_big"` and a 4.5 MiB `input`; then emit a `can_use_tool` control request with `tool_use_id: "toolu_big"` and the 4.5 MiB `input`, and feed `GateDecision::Ask { ticket }`.
   - Result:
     - `adapter.rs:946` computes `let big = line.len() > MAX_PARTIAL_ARGS_BYTES;` and passes `big` only to `on_hook`, not to `on_can_use` (`adapter.rs:986`). `on_can_use` spawns `gate.check` with the 4.5 MiB `input`.
     - In Case A, `emit_approval` (`normalizer.rs:904-933`) has no `value_size(&c.input) > MAX_PARTIAL_ARGS_BYTES` check: it inserts `"toolu_big"` into `self.seen_calls` and emits both `ToolCallStarted` and `ApprovalRequested` containing the raw 4.5 MiB `input` (`> MAX_EVENT_BYTES` = 1 MiB in `limits.rs:34`, which causes `atrium_daemon::sessions` to fail `store.append` with `StoreError::EventTooLarge` and abort the session). Worse, when the `assistant` `tool_use` arrives next (`normalizer.rs:562`), `self.seen_calls.insert(id)` returns `false`, so the oversize check at `normalizer.rs:572` is skipped completely!
     - In Case B, `tool_use` (`normalizer.rs:572-590`) marks `"toolu_big"` failed (`ToolCallStarted` with `{"_truncated": true}` + `ToolCallFinished { status: Failed }`) and inserts `"toolu_big"` into `self.done_calls`, but `emit_approval` (`normalizer.rs:904`) never checks `self.done_calls.contains(&c.call_id)`, so it emits `ApprovalRequested` with the 4.5 MiB `input` for a tool call that has already finished!
     - Violates `crates/atrium-protocol/src/limits.rs:28-35` (`MAX_PARTIAL_ARGS_BYTES`, `MAX_EVENT_BYTES`) and `crates/atrium-agents/src/lib.rs:58`.
   - Fix: Pass `big` into `on_can_use` (`adapter.rs:986, 1061`) and immediately deny with `"tool input exceeds limit"` when `big || value_size(&input) > MAX_PARTIAL_ARGS_BYTES` (just like `on_hook` at `adapter.rs:1022-1028`). In `normalizer.rs:887` (`can_use_tool`) and `normalizer.rs:904` (`emit_approval`), drop/ignore requests where `value_size(&input) > MAX_PARTIAL_ARGS_BYTES` or `self.done_calls.contains(&call_id)`.
