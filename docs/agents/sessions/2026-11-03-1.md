## Next

1. **Pedro: two decisions from the Linux checks** (`docs/spikes/M0-linux-checks.md` §5):
   - **L2, the memory metric on Linux.** Linux PSS doesn't measure the same thing as macOS `phys_footprint`: it includes shared-library pages and excludes GPU memory. One window is about 144 MB without shared libraries, about 275 MB as full PSS, and about 310 MB with GPU added. Pop-outs cost about 75 MB PSS each on Linux, plus GPU, against about 35 MB on macOS (D-028).
   - **L10, 60 fps pacing.** WebKit's `PreferPageRenderingUpdatesNear60FPS` is on by default in WebKitGTK 2.54, and WebKit on macOS has a preference of the same name, so Atrium renders near 60 fps on 120/144 Hz displays. Decide whether M1 turns it off, trading power for smoothness.
2. **Finish G6** (Linux checks before M1 UI work merges). Still open:
   - **Frames at 120/144 Hz.** GNOME opens new windows on the primary monitor, so make the fast monitor primary, or set the laptop panel to 120 Hz. Then, in `spikes/ui-shell`, run `env ATRIUM_WEBKIT_NATIVE_FPS=1 python3 scripts/measure.py frames --runs 3 --windows 1 --hz <rate>`, plus one run without the variable. The `linux-display` lines in the run log confirm which monitor each window landed on.
