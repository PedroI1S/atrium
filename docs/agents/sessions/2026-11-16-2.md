## Mistakes and lessons (orchestration)

- **A shared `CARGO_TARGET_DIR` across worktrees mixed builds:** a test binary ran against another worktree's `atrium-core`. Two verifications reported failures that weren't there, and one rework prompt chased an ordering problem that didn't exist. **Each worktree now builds in its own `target/`.**
- **Waiting loops deadlocked.** `while pgrep -f verify.sh` matched the other waiting loops, whose command lines contain `verify.sh` too. **Use `.orchestration/verify-queue.sh`, never a `pgrep` wait.** The same mistake twice: `pkill`/`kill $(pgrep -f …)` with a pattern found in the calling shell's own command line killed that shell (exit 144). Kill by a PID list taken with `ps` first.
- **Two prompts went out with the wrong handoff path** (M1-30 and M1-31 pointed at M1-27's). They were stopped within a minute, before any change.
- **The `agy` quota stopped three runs mid-way.** One left uncommitted work, which the orchestrator committed as WIP (`3b43254` on M1-32). A watcher that had already exited missed the M1-28 review's end for 1h30.
- **The watchdog** (`.orchestration/watchdog.sh`) had two false alarms, a test sleeping and a gap between test binaries. It now counts any process of the worktree's target as alive; a test running over 10 minutes is still flagged.
