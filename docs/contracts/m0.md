## 3. Fixtures

- Format and golden tests: `crates/atrium-agents/src/fixture.rs`. Files: `fixtures/agents/<provider>/<scenario>.{jsonl,events.json,md}`.
- **Required scenarios per adapter** (each one recorded live, sanitized, with a golden test):
  1. `simple`: a one-line answer, no tools.
  2. `tool-read`: the agent reads a file (an auto-allowed tool).
  3. `approval-allow` and `approval-deny`: a command that needs approval, answered both ways.
  4. `multi-turn`: two user messages in one session.
  5. `resume`: a second process resumes the first session by native id.
  6. `error`: an invalid model id (or the provider's equivalent startup error).
- Sanitize everything committed: `~` for the home dir, `user` for the user name, no tokens, no env values, no account emails.
- A worker who can't run the provider CLI in its own sandbox writes the live harness (`cargo run -p <crate> --example record -- <scenario>`) and hand-made fixtures from the provider's documented schema, says so in the handoff, and the orchestrator records the real fixtures during verification.

## 4. UI tokens (M0-06 implements, the M1 app inherits)

PLAN §3.20. Three layers, all CSS custom properties, set at runtime on `:root`:

1. **Primitive**: `--p-<palette>-<step>` (e.g. `--p-gray-50 … --p-gray-950`, `--p-accent-500`), `--p-space-<n>`, `--p-radius-<n>`, `--p-font-<role>`, `--p-text-<size>`, `--p-duration-<speed>`.
2. **Semantic** (components use only these and layer 3). Required set; a theme that misses one fails validation:
   - surfaces: `--surface-0` (window), `--surface-1` (panels), `--surface-2` (raised), `--surface-overlay`, `--surface-glass` (vibrancy panels, with alpha)
   - text: `--text`, `--text-muted`, `--text-faint`, `--text-on-accent`
   - lines: `--border`, `--border-strong`, `--focus-ring`
   - accent + states: `--accent`, `--accent-hover`, `--accent-muted`, `--danger`, `--warning`, `--success`, `--info`
   - code and diffs: `--code-bg`, `--diff-add`, `--diff-del`, `--diff-add-text`, `--diff-del-text`, `--ghost-text`
   - attention states (§3.4): `--state-running`, `--state-needs-you`, `--state-failed`, `--state-ready`
   - density and motion: `--space-unit`, `--radius`, `--font-ui`, `--font-code`, `--text-ui`, `--text-code`, `--motion-fast`, `--motion-normal`
3. **Component**: `--<component>-<property>`, e.g. `--tab-active-bg`, `--composer-radius`, `--sidebar-width`. Defaulted from semantic tokens in the component's CSS; a theme may override them.

**Theme file** `themes/<name>.toml`:

```toml
[meta]
name = "Atrium Dark"
appearance = "dark"            # dark | light
vibrancy = true                # use --surface-glass + native blur where available

[primitive]
gray-50 = "#f7f7f8"            # → --p-gray-50
# …

[semantic]
surface-0 = "{gray-950}"       # "{name}" references a primitive
accent = "#7c8cff"             # or a literal
# …

[component]                    # optional overrides
tab-active-bg = "{surface-2}"
```

- References resolve primitive → semantic → component; a cycle or a missing reference is a load error.
- Switching themes replaces the variables in place, with no reload. The loader validates the required semantic set and checks WCAG AA contrast for `--text`/`--text-muted` on `--surface-0..2` and `--text-on-accent` on `--accent`.
- VS Code import maps `colors` → semantic tokens. The mapping table is part of the M0-06 report; Shiki/CodeMirror themes come from `tokenColors`.
